# 06. Non-functional Requirements

## 1. セキュリティ

### NFR-SEC-01 — テナント分離

Workspace、Project、Model、GenerationRunへの全アクセスでサーバ側認可を行い、他テナントIDを指定したアクセスが成立しないことを自動検証する。

### NFR-SEC-02 — 認証・権限

- 初期SaaSは安全な認証プロバイダを利用する。v0.1 のサーバーはパスワード（argon2id）と、認証プロキシ（OIDC 等）のヘッダーを信頼する方式を持つ。ユーザー名だけの簡易ログインは、loopback で待ち受けてパスワード付きアカウントがないとき（または明示的に有効にしたとき）に限る（docs/09 §11）。
- 既定ではローカル（127.0.0.1）だけで待ち受ける。ネットワークに出すときは、ホスト名の許可リスト（DNS リバインディング対策）・Origin と JSON の確認（CSRF）・セキュリティヘッダー（CSP 等）・要求の大きさの上限を常に適用する。
- サーバーの費用を使う機能（AI）は、運用者が許可した利用者だけが有効にでき、利用者ごとに呼び出し回数を制限する。
- Owner / Editor / Viewerの最小権限を適用する。
- 高権限操作、メンバー変更、Git連携、削除を監査記録に残す。
- 将来の企業向けSSO/SCIMは顧客需要確認後に提供する。

### NFR-SEC-03 — Secret管理

- GitHubトークン、API key等は暗号化して保管し、ログへ出さない。
- トークンの最小権限とローテーション・解除をサポートする。
- 生成モデルや例にSecretを含めないようUIで警告する。

### NFR-SEC-04 — DSL安全性

- モデル解析で任意コード、ファイルアクセス、シェル実行を許さない。
- Rule式評価は時間・メモリ上限を持ち、純粋関数に限定する。
- AI生成物やユーザー入力を実行する場合は隔離環境を使い、生成処理とSaaS本体を分離する。

## 2. プライバシー・顧客データ

- ドメインモデルは企業秘密を含みうる機密情報として扱う。
- 収集データ、保存場所、保持期間、バックアップ、削除期限を明記する。
- 顧客の同意なしにモデル・コードをAI学習へ利用しない。
- テレメトリは既定で個人情報やモデル本文を含めず、無効化可能にする。
- エクスポートとアカウント削除手順を提供する。
- データ所在地や法令遵守の要件は、最初の対象市場と導入顧客を確認して決定する。

## 3. 信頼性・可用性

- Web SaaSの初期目標可用性は99.5%/月を仮置きする。PoCの必要水準を顧客と確認後に確定する。
- SaaSが停止しても、顧客は保存済みモデルとCLIで検証・生成を続けられる。
- モデル保存は競合編集を検出し、変更を黙って上書きしない。
- バックアップ復元を定期的に確認し、RPO/RTOを事業要件に合わせて定義する。
- 生成処理は再試行可能であり、部分書き込みを検出・回復できる。

## 4. 性能・拡張性

- 初期目標: 100要素程度のContextをローカルCLIで5秒以内に検証・生成（一般的な開発用端末、キャッシュなし）。
- Web上でモデル要素の検索・参照移動を1秒程度で応答することを目指す。
- 実測用のベンチマークモデルとCI計測を用意する。
- 制限値を超えるモデルには、失敗理由と分割・改善案を返す。

## 5. 保守性・互換性

- モデル形式、IR、ジェネレータを個別にバージョン管理する。
- Generatorの各版でサンプルモデルとGolden testsを保持する。
- 生成コードのformatter/linter/型checkerをCIで実行する。
- 出力形式変更による大規模差分を事前に可視化し、マイグレーション手順を用意する。
- CLIのサポート期間・セキュリティ更新方針を公開する。

## 6. アクセシビリティ・学習容易性

- DDD用語に説明と小さな実例を付ける。
- 図の色だけで意味を伝えず、ラベル・アイコン・テキストでも状態を表す。
- キーボード操作とスクリーンリーダーでモデルの主要操作を実行できる。
- エラー文をPython内部構造ではなく、ドメイン要素名と修正手順で示す。
- 初回導線でEntityとValue Object、InvariantとStateGuardの違いを短い例で説明する。

## 7. 運用・監視

- エラー率、生成所要時間、失敗コード、CLI互換性を監視する。
- モデル本文・生成コードを通常のログへ記録しない。
- 顧客がサポート問い合わせ時に添付する診断Bundleは、送信前に内容を確認できる。
- 障害対応、セキュリティ報告、依存パッケージ更新、バックアップ復元の手順を用意する。
