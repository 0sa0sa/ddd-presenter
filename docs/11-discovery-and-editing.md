# 11. ディスカバリーボードと編集支援の使い方

モデルを書く前の「何を集約にするか・どこでコンテキストを切るか」を決める段階から、YAML を書く段階までを支援する機能のガイド。設計上の決定は [docs/09](09-implementation-decisions.md) §5 を参照。

## 1. ディスカバリーボード（EventStorming）

プロジェクトの「ディスカバリー」タブ。モデルに Aggregate がまだないプロジェクトはこのタブから開く。

### 進め方の目安

1. **ドメインイベントを並べる** — 業務で起きた出来事を過去形で、時系列に左から右へ（「招待が送られた」「招待が受諾された」）。細かさより数を優先する。
2. **コマンドとアクターを置く** — そのイベントを起こす操作（「招待を受諾する」）と、実行する人（「スタッフ候補」）。アクター → コマンド → イベントを矢印でつなぐ。
3. **ポリシーを書く** — 「〜されたら〜する」自動の反応。イベント → ポリシー → コマンドとつなぐ。
4. **論点を残す** — 疑問・対立はホットスポット（赤）に書いて先に進む。
5. **集約を決める** — コマンドを受けて、一度の変更で必ず守るルールを持つまとまり。コマンドから集約へ矢印を引き、守るルールをルール付箋で書く。
6. **コンテキストの境界を引く** — 付箋を範囲選択して「コンテキストで囲む」。言葉の意味が変わる所・担当が変わる所・ポリシーでつながる所が候補。
7. **モデルに反映する** — 「モデルに反映…」で英字の名前を決め、差分を確認して YAML に入れる。

### 操作

| 操作 | 方法 |
|---|---|
| 付箋を置く | ツールバーの種類をクリック（画面中央に置く）／キャンバスをダブルクリック（その場所に置く） |
| テキストを編集 | 付箋をダブルクリック、または選んで Enter。⌘/Ctrl+Enter で確定、Esc で取消 |
| 矢印を引く | 付箋にマウスを乗せると出る端の丸からドラッグ |
| 範囲選択・移動 | 空いている所をドラッグで範囲選択／ホイールか右ドラッグで画面を移動 |
| 削除・複製・元に戻す | Delete／⌘D／⌘Z（やり直しは ⌘⇧Z） |
| フレーム | フレームを動かすと中の付箋も一緒に動く。付箋の所属は位置で決まる |

変更は自動で保存される。ほかの人の変更は数秒で画面に反映される。同時に保存して衝突したときは、どちらを残すかを選ぶダイアログが出る。

### 整理の補助（右パネル）

- **ヒント** — EventStorming でよくある抜けを指摘する（過去形でないイベント、結果のイベントがないコマンド、誰が実行するか分からないコマンド、コマンドを受けない集約、ルールのない集約、未解決の論点、どのコンテキストにも入っていない付箋、大きすぎるコンテキスト）。クリックすると該当の付箋へ移動する。
- **集約の候補** — 矢印と配置から、同じものを変更するコマンド・イベントのまとまりを示す。集約がまだないまとまりには、文中に共通する名詞から名前の案を出し、「集約として置く」で付箋を置ける。**候補は提案であり、集約にするか・どこで分けるかはチームが決める。**
- **コンテキスト** — フレームごとの集約・コマンド・イベントの数と、フレームをまたぐ「イベント → ポリシー → コマンド」の連携（コンテキストマップの候補）。

### モデルへの反映で起きること

| ボード | モデル |
|---|---|
| フレーム | Bounded context（フレームがなければ `Core`） |
| 集約 | Aggregate（`id: UUID` を識別子にする） |
| 集約につながるコマンド | Operation と、それを呼ぶ Use case（load → invoke → save → publish_after_commit）。「このコマンドで集約を新しく作る」にチェックしたものは Factory と create の Use case |
| コマンドから出るイベント | Operation の emits |
| アクター | Use case の actor |
| ルール付箋 | Aggregate の説明に `TODO ルール: …` として残す（条件式は推測しない） |
| 日本語のラベル | 用語集（ラベル → 英字名） |
| ポリシー・ホットスポット・リードモデル・外部システム | 反映しない（理由を表示） |

既存のモデルがある場合は、足りない要素だけを追加し、既にある要素は変更しない。推測が必要なもの（フィールドのある既存 Aggregate へのファクトリ追加、引数が必要な既存操作の Use case など）は理由を付けて「手で書くもの」として示す。反映した内容は YAML エディタに未保存の変更として入るので、フィールド・状態変更・Rule・シナリオを書き足してから保存する。

## 2. YAML エディタの補完（Web・VS Code 共通）

同じ言語サービス（`packages/core/src/language.ts`）が、Web のエディタと VS Code 拡張の両方で動く。

| 機能 | Web | VS Code |
|---|---|---|
| 補完 | 入力中に自動、Ctrl+Space | 入力中に自動、Ctrl+Space |
| 説明の表示 | マウスを乗せる | マウスを乗せる |
| 定義へ移動 | ⌘/Ctrl+クリック、F12 | ⌘/Ctrl+クリック、F12 |
| 名前の一括変更 | F2（型と State guard） | F2（型と State guard） |
| 診断 | 下の一覧と行の印 | 問題パネルと波線 |

補完が出る場所の例:

- キー — その場所で書けるキーと意味（既に書いたキーは出さない）
- `type:` — 組み込み型、Enum、Value Object、同じ Aggregate の Entity、`List[`、`Ref[`
- `error:` / `raises:` / `not_found:` / `fail:` — Domain error
- `publish_after_commit:` — そのコンテキストのイベント
- `operation:` — 読み込んだ変数の Aggregate の操作。`save:` / `target:` — それまでに読み込んだ変数
- Rule 式 — フィールド・引数・関数。`status == ` の後や `changes` の Enum フィールドでは Enum 値を先頭に出す。`require:` では State guard。Use case の条件では入力・変数・`変数.ガード`・`clock.now`・`ids.new`・Extension point
- シナリオのデータ — Enum フィールドの値

### VS Code 拡張のインストール

```sh
bun run build:vscode      # packages/vscode/ddd-presenter-0.1.0.vsix を作る
code --install-extension packages/vscode/ddd-presenter-0.1.0.vsix
```

`*.ddd.yaml` を開くと有効になる（ネットワークには接続しない）。

## 3. 予測と提案（Tab で書き進める）

GitHub Copilot のように、次に書きそうな内容を半透明で先に表示し、Tab で確定できる。予測には2種類ある。

- **ローカルの予測**（常に使える・送信なし）: モデルの構造から決まる続き。`packages/core/src/assist.ts`。
- **AI の予測**（ワークスペースで有効にしたときだけ）: AI がモデル全体を読んで続きを書く。ワークスペースのオーナーが「設定」タブで、使う AI を選んで有効にする。オンのあいだ、予測・提案のたびにモデル（YAML）やボードの内容が選んだ AI に送られる。切り替えは監査ログに残る。

### 使える AI

サーバーは起動時に、使える AI を見つけて「設定」タブの選択肢に出す。

| AI | 条件 | 送信先 |
|---|---|---|
| Claude API | サーバーに `ANTHROPIC_API_KEY`（または `ANTHROPIC_AUTH_TOKEN`）を設定 | Anthropic |
| Claude Code（ローカルCLI） | サーバーのマシンで `claude` が使え、ログイン済み | Claude Code 経由で Anthropic |
| Codex CLI（ローカル） | サーバーのマシンで `codex` が使え、ログイン済み | Codex 経由で OpenAI |

- ローカルの CLI は、API キーなしで、手元の Claude / ChatGPT のサブスクリプションで使える。サーバーを動かしているマシンのログインを使うので、チームで共有するサーバーでは、そのアカウントの利用枠を全員で使うことになる。
- CLI はコーディングエージェントとしてではなく、文章の生成だけに使う。Claude Code は `--tools=`（ツールなし）・MCP なし・ユーザー設定とフックなし・独自のシステムプロンプトで、Codex は read-only のサンドボックスでシェル・ブラウザ・プラグインを無効にして動かす。どちらも空の一時ディレクトリで起動する。
- 1回の予測は数秒〜数十秒かかる（CLI の起動を含む）。入力を続けると、途中の呼び出しは止める。同時に動かす CLI は最大2つ。
- Claude Code の予測は既定で速いモデル（`haiku`）、提案は CLI の既定モデルを使う。

| 環境変数 | 意味 |
|---|---|
| `DDD_AI` | `off` で AI を使わない。`claude-code,codex` のように書くと、その AI だけを選択肢に出す |
| `DDD_AI_MODEL` / `DDD_AI_INLINE_MODEL` | Claude API・Claude Code のモデル（提案用 / 予測用） |
| `DDD_AI_CODEX_MODEL` / `DDD_AI_CODEX_INLINE_MODEL` | Codex のモデル |
| `DDD_CLAUDE_BIN` / `DDD_CODEX_BIN` | CLI の場所（PATH にない場合） |

### YAML エディタ

| 操作 | キー |
|---|---|
| 予測を確定 | Tab（補完の一覧が出ているときは補完が優先） |
| 予測を消す | Esc |
| 今すぐ予測する | ⌥\ / Alt+\ |

予測は行末で、入力が止まってから表示される（ローカルは約0.35秒後、AI は約0.9秒後で、届いたらローカルの予測と入れ替わる）。ローカルの予測が出る場所:

| カーソルの場所 | 予測される内容 |
|---|---|
| `operations:` の新しい項目 | まだどの操作も遷移させていない状態へ進む操作（例: `revoke`）。State guard・`changes`・既存の命名に合わせたイベント（`InvitationRevoked`）つき |
| `emits:` の後 | 操作名から作ったイベントと、運ぶフィールド（識別子と引数） |
| `changes:` の後 | 操作名から推測した、状態フィールドの次の値（`revoke` → `status: revoked`） |
| `require:` の後 | その操作に合う、いちばん単純な State guard |
| `state_guards:` の新しい項目 | まだない状態のガード（`is_pending` など）とエラー |
| `scenarios:` の新しい項目 | ガードに違反して失敗するケース（Invariant に先に弾かれない状態を選ぶ）か、成功するケース。値は `user@example.com` のように型と名前から具体的に作る |
| `use_cases:` の新しい項目 | どの Use case からも呼ばれていない操作を呼ぶ手順 |
| `errors:` の新しい項目 | 参照されているのに定義されていない Domain error |

どの予測も、確定したときにエラーが増えないものだけを表示する（AI の予測もサーバーで同じ確認をする）。

### 集約への提案（差分で確認）

アウトラインや図で Aggregate を選ぶと、右の詳細に「提案してもらう」が出る。「次の操作」「ルール」「シナリオ」「イベントの内容」を押すと、提案が差分で表示される。適用するまでモデルは変わらず、適用しても未保存の変更として入る。提案には次の3つが分けて書かれる。

- モデルからわかっていること（事実）
- 推測（チームで確認すること）
- ドメインエキスパートへの質問

AI が有効なら、自由な指示（「招待の再送を追加して。再送は3回まで」など）でも提案させられる。AI の提案が検証エラーになった場合は、エラーを伝えて一度だけ直させる。

### ディスカバリーボード

付箋を置くと、その並びから次に置きそうな付箋が半透明（点線の枠）で表示される。クリックまたは Tab で本物の付箋と矢印になり、× か Esc で消える。ツールバーの「予測を表示」で表示を止められる。

- コマンドの右に、それが成功したときのイベント（「招待を受諾する」→「招待が受諾された」）
- イベントの左に、それを起こすコマンド（「招待が取り消された」→「招待を取り消す」）
- 集約につながっていないコマンドのまとまりに、集約の案

選択中の付箋（なければ最後に置いた付箋）に関係する予測だけを表示する。AI が有効なら「AI に付箋を提案してもらう」で、足りなさそうなアクター・ポリシー・ホットスポットなどもまとめて提案される（紫の枠）。
